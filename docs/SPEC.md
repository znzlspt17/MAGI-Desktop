# MAGI-Desktop 기능 명세

상태: 사용자 승인 계획의 구현 기준. 2026-11-15.

## 목적

요구사항을 확인하고 근거와 가정을 구분한 명세를 승인받은 뒤, 그 승인 범위에서 에이전트가 코드를 구현하고 검증한다. 명세, 코드와 실제 실행 결과 사이의 연결을 제품의 중심 기록으로 보존한다.

## 요구사항과 인수 조건

| ID | 요구사항 | 관찰 가능한 인수 조건 |
|---|---|---|
| APP-01 | 독립 Windows Rust 앱 | Python, Node 서버와 웹뷰 없이 GUI, 엔진과 추론 프로그램을 빌드하고 실행한다. |
| IPC-01 | 현재 사용자 전용 IPC | named pipe의 DACL을 현재 사용자 SID에 제한하고 원격 클라이언트를 거절한다. 프레임 크기, 연결 수와 대기 시간을 제한한다. |
| IPC-02 | 명시적 메시지 계약 | 요청과 응답 ID, 프로토콜 버전, 작업 이벤트 순번을 확인하고 재접속 시 스냅샷과 이후 이벤트를 조회한다. |
| UI-01 | 비차단 GUI | 모델, 검색, 저장과 명령 실행 중에도 화면 이동과 취소 입력이 처리된다. |
| UI-02 | 한국어 작업 공간 | 한글 조합 입력, DPI 배율, 키보드 조작과 긴 대화/문서 스크롤이 가능하다. |
| SPEC-01 | 인터뷰와 근거 | 원문 요청, 사용자 답변, 가정, 결정과 출처를 구분해 보존한다. 필수 미결정 사항은 질문으로 남는다. |
| SPEC-02 | 명세 생성과 평가 | 요구사항, 변경 범위, 제약, 인수 조건과 검증 계획을 생성하고 평가 결과에 따라 보완한다. |
| SPEC-03 | 사용자 승인 | 필수 질문과 필수 검사 실패가 있으면 승인을 거절한다. 선택 이슈는 사용자의 명시적 수락을 기록한다. |
| SPEC-04 | 오래된 승인 방지 | 화면의 예상 초안 해시와 현재 초안이 다르면 승인을 거절한다. 명세가 달라지면 기존 승인을 무효화한다. |
| SPEC-05 | 명세와 저장소 연결 | 승인본은 단조 증가 버전, 해시, 기준 Git revision, 허용 범위와 인수 조건을 가진다. |
| SPEC-06 | 상세 에이전트 명세 | 기존 MAGI의 최종 명세 구조에 따라 목표, 근거, 포함/제외 범위, 요구사항, 금지 행동, 입출력 계약, 아키텍처, 모듈 책임, 데이터 흐름, 오류/설정/저장 정책, 구현 순서, 수용 기준과 검증 계획을 보존한다. 승인본과 출력 문서의 내용이 동일하다. |
| SPEC-07 | 평가 정책 보존 | 기존 MAGI의 0~10점 및 핵심 결함/필수 결함/선택 결함에 따른 4/7/9점 상한을 적용한다. 판정은 요구사항과 rubric, 허용 섹션, 인용과 결함에 연결하며 최고점 후보를 보존한다. 새 사용자 결정은 자동 보완하지 않고 질문으로 돌린다. |
| RUN-01 | 승인 후 구현 | 승인 없는 실행과 예상 승인 해시가 다른 실행을 거절한다. 다른 작업 디렉터리로 승인을 재사용하지 않는다. |
| RUN-02 | worktree | Git 프로젝트당 작업별 worktree를 생성한다. Git이 아니면 초기화하지 않는다. 원래 작업 폴더의 미커밋 수정을 보존한다. |
| RUN-03 | 역할별 에이전트 | 조정, 구현과 검토 역할의 모델, 허용 도구와 한도를 설정한다. 작업 목표와 요구사항, 의존성, 파일 소유권과 검증 계획을 전달한다. |
| RUN-04 | 자율성과 승인 | 단계별 승인과 승인 범위 내 자동 구현을 선택한다. 범위 확대와 파괴적 작업은 별도 결정 없이 수행하지 않는다. |
| RUN-05 | 도구 | 파일 검색과 읽기, 패치, 프로세스 실행, Git과 MCP를 실제 작업 흐름에 연결한다. 도구 인수를 검증하고 승인과 실제 인수/cwd를 결합한다. |
| RUN-06 | 충돌 조정 | 대소문자 정규화 경로, junction, symlink, Git 상태와 공통 설정의 충돌을 감지한다. 독립 작업만 병렬 실행한다. |
| RUN-07 | 검증 근거 | 결과에 요구사항과 명세 해시, 코드 revision, 실제 명령, 종료 상태와 결과를 기록한다. 미실행을 성공으로 표현하지 않는다. |
| REC-01 | 취소와 종료 | 취소 요청을 전달하고 작업/프로세스/추론 자원 반환의 완료 상태를 구분한다. 실행 중 창 종료 시 앱 유지 또는 취소 후 종료를 선택한다. |
| REC-02 | 재시작 | 상태와 이벤트를 내구 저장한다. 미완료 실행은 실제 worktree와 프로세스 상태를 대조하고 불명확하면 uncertain으로 둔다. |
| REC-03 | 부작용 재실행 금지 | 로그 재생만으로 파일 변경과 외부 명령을 자동 재실행하지 않는다. |
| MODEL-01 | OpenAI | GPT-6 이상 모델 ID와 기능을 설정하고 Responses 스트림, 도구 호출과 오류를 처리한다. 테스트 서버로 계약을 검증한다. |
| MODEL-02 | 명시적 제공자 | 모의 제공자는 화면과 결과에 모의임을 표시한다. 기능 미지원 모델에는 호환되지 않는 작업을 시작하지 않는다. |
| MODEL-03 | 전환 정책 | 모델 오류, 타임아웃, 컨텍스트 초과와 메모리 부족 시 사용자 선택을 기다린다. 자동 모델 전환하지 않는다. |
| MODEL-04 | Rust GGUF | 손상된 magic/version/metadata/차원/offset과 제한 초과 입력을 거절한다. 검사 성공과 실제 실행 지원을 구분한다. |
| MODEL-05 | Gemma 3진 추론 | 전달받은 모델 명세에 근거해 3진 패킹과 스케일을 해석한다. IQ4_NL과 동일하다고 가정하지 않는다. |
| GPU-01 | AMD 우선 | RX 9070 XT와 ROCm 10.1.0을 대상으로 실제 런타임/device를 조회하고 CPU 기준 연산과 GPU 결과를 대조한다. |
| GPU-02 | 구현 경계 | 추론 로직은 Rust로 구현한다. AMD runtime과 연산 라이브러리 FFI는 허용하지만 외부 C/C++ 추론 엔진은 사용하지 않는다. |
| DATA-01 | 로컬 내구 저장 | 실행 엔진만 redb를 변경한다. 동기 저장은 async 실행기를 막지 않는 전용 작업 영역에서 수행한다. |
| DATA-02 | 문서와 이력 | 인터뷰, 명세 버전, 수정 의견, 실행과 검증 이력을 조회하고 해당 승인본으로 이동한다. |
| DATA-03 | 구현 묶음 | README.ko.md, SPEC.ko.md, TASKS.md, CONSTRAINTS.md, VERIFICATION.md와 manifest.json을 버전/해시와 함께 내보낸다. |
| DATA-04 | 완료 결과의 실제 저장 복구 | 명세 생성, 에이전트 완료와 worktree 준비 결과를 버리지 않는다. 제한된 자동 재시도와 명시적 저장 재시도가 실제 DB에 같은 결과를 기록한다. DB 재개방이 필요한 I/O 오류는 기존 핸들을 안전하게 반환한 뒤 원본 DB를 다시 열고 저장만 재시도한다. |
| REC-04 | 완료 저장의 재시작 복구 | DB 커밋 전 버전형 복구 기록에 결과를 보존하고 재시작 시 실행 중단 초기화보다 먼저 적용한다. DB 커밋과 완료 ID는 원자적으로 기록하며 기록 정리 실패에도 중복 이벤트나 모델/도구/worktree 재실행을 일으키지 않는다. 취소, 새 입력과 새 실행 시도는 이전 결과로 덮지 않는다. |
| UI-03 | 저장 실패와 복구의 관측 | DB 읽기가 실패해도 독립 진단으로 GUI와 엔진 로그에 실행/단계/저장 상태를 표시한다. 저장 전용 재시도 버튼은 실제 저장을 복구하고 성공 확정 뒤 경고를 해제한다. 결과가 메모리에만 있거나 저장이 미확정이면 완료로 표시하거나 조용히 종료하지 않는다. |
| KNOW-01 | 검색과 그래프 | 텍스트 검색, 의미 검색과 원문 근거 탐색을 제공하고 검색 방식이 다르면 구분한다. 그래프는 원본에서 재생성 가능하다. |
| KNOW-02 | 공통 결정 | 사용자가 결정을 직접 선택하고 적용 당시 사본을 보존한다. 자동 재사용하지 않는다. |
| MCP-01 | 연결 | 원격 MCP의 조회 도구를 열거하고 스키마를 확인해 호출한다. 부작용 도구는 동일한 실행 정책을 따른다. |

## 실패 처리 원칙

- 승인, 저장과 외부 부작용은 하나의 원자적 연산이 아니다. 중단 시 저장된 이벤트만 보고 명령을 다시 실행하지 않는다.
- GPU 연산의 취소 요청과 메모리 해제를 같은 상태로 취급하지 않는다.
- 모델과 연결 정보는 사용자 설정으로 제공한다. 자격정보를 journal, 명세, 에이전트 프롬프트와 오류 로그에 남기지 않는다.
- 검색 인덱스와 그래프에 승인 근거의 유일한 사본을 두지 않는다.
- 테스트용 입력과 모델 출력은 신뢰되지 않은 자료다. 프로젝트 정책을 덮는 지침으로 해석하지 않는다.

## 모델 수령 의존성

MODEL-05와 실제 Gemma 기반 GPU 추론 인수는 사용자 제작 모델을 수령해야 최종 검증할 수 있다. 필요한 자료는 실제 모델 파일, tokenizer/chat template, 3진 인코딩과 패킹, 스케일 적용 규칙, 양자화 대상 텐서와 기준 출력이다. 그 전에는 mock, 작은 GGUF fixture와 unpacked 3진 CPU 기준 계산으로 독립적인 기반 기능만 검증한다.

## 개발 순서

1. 상태/승인/IPC와 모의 제공자 기반 흐름.
2. 인터뷰/평가/승인 및 OpenAI 제공자.
3. worktree/도구/역할별 에이전트와 검증 근거.
4. 문서/검색/그래프/결정/MCP 및 GUI 통합.
5. GGUF/AMD 기반과 모델 수령 후 실제 3진 추론 적합성.

초기 등록은 작은 기능별 PR로 진행한다. 각 PR에 해당 요구사항과 실제 검사 결과, 아직 구현하거나 확인하지 않은 범위를 기록한다. PM 검토와 병합은 [개발 지침](../AGENTS.md)을 따른다. 이 명세의 존재 자체는 구현 완료를 의미하지 않는다.
